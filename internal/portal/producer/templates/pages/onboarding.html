Step 2: register an event type

The contract you publish against: a name, a routing mode and a JSON Schema the API validates every publish of this type against.

{{template "csrf_field" .}}
An empty box registers {"type":"object"}, which accepts any JSON object. Anything else must be a JSON document or the form refuses it before the API sees it.

Step 3: register a consumer and an endpoint

A consumer is your customer; an endpoint is a URL that customer's systems receive your events at. Both are created by one submit: the consumer first, then the endpoint inside it.

{{template "csrf_field" .}}
FR-402's escape hatch: private, loopback, link-local and metadata ranges are refused unless the endpoint is marked internal, for an endpoint you own on a private network.

Step 5: send yourself a test event

A test event is a real event: it is validated, fanned out, delivered and logged exactly like production, and marked as a test wherever it appears (UI-4).
