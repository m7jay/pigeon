Publishing and fan-out

Publish one event with a single POST naming this type and carrying a payload; the API validates that payload against the schema above before anything else happens, and the payload version is the one this page shows.{{if eq .RoutingMode "consumer"}} A consumer-routed event must name exactly one consumer - consumer_ref - and fan-out is the active endpoints of that consumer intersected with the active subscriptions for this type (FR-505, FR-507). An event naming both or neither is refused with a 422.{{else if eq .RoutingMode "broadcast"}} A broadcast event names no consumer: it takes no consumer_ref, and supplying one is a 422 (FR-505).{{end}} Each delivery that fan-out produces is signed with its endpoint's own secret, retried independently, and kept with its full attempt trail - so what you see in the delivery log is what the consumer sees, minus the other consumers.

Verifying what you receive

Signatures are Standard Webhooks. Take the endpoint's whsec_ secret to the snippets page for a verifier in curl, Go, Node or Python - during a rotation, accept the old and the new signature until the overlap window closes (UI-6).
